Ruby driving real Java libraries, in your browser

The Ruby code next to the canvas runs in JRuby, compiled to JavaScript with TeaVM. It uses two unmodified Java libraries from Maven Central, compiled into the same jruby.js: JBox2D (the Java port of the Box2D physics engine) and ZXing (QR codes), and it draws through demo.Canvas2D, a small Java class over the canvas. CRuby and ruby.wasm cannot load Java libraries. Edit the code and run it again with Ctrl+Enter. Plain Ruby REPL · More Ruby calling Java

How this works
    
The jars of JBox2D 2.2.1.1 (BSD-2-Clause) and ZXing core 3.5.4 (Apache-2.0) go through the same TeaVM build as
      JRuby. The classes listed in java-classes.txt get reflection metadata, so JRuby's Java integration
      can call them from Ruby: World.new(Vec2.new(0, -10)), Ruby blocks as Java interfaces, Ruby objects
      stored in Java fields. canvas.animate { } runs its block once per requestAnimationFrame,
      on a green thread of its own, and clicks reach the on_click block on that thread between two
      frames. Each frame of the physics demo is Ruby code: one world.step into JBox2D, then a Ruby loop
      over all bodies that reads each position and draws it, seven or eight Ruby-to-Java calls per body.
